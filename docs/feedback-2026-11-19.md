## 1. Wheel zoom over nodes

- Feedback: the mouse wheel does not zoom the canvas when the pointer is on a node. One
  navigation in the canvas is more important than a wheel input on a node control.
- Cause: the node GUI has the class `nowheel` (`controls/NodeGui.tsx`). React Flow and the
  touchpad pan (`canvas/touchpad.ts`) ignore a wheel event in a `nowheel` element.
- Fix: remove `nowheel` from the node GUI. The wheel zooms and the touchpad pans at all places on
  the canvas. A long code field on a node scrolls with its scroll bar.
- Spec: 15.2, the rule "A node GUI keeps its own wheel input" changes.

## 2. The 3D view shows the desktop after Run

- Feedback: after **Run**, the 3D view area shows the windows under the editor. A close and an
  open of the workbench repairs it.
- Cause, from the logs of the owner's test copy: the view builds in the mode of the loaded
  cluster (15.8). **Run** builds the cluster in Bake mode, so the editor drops the Edit build of
  the view and builds the view again in Bake mode (about 45 s for the gun). The drop removes the
  native child window. The page stays transparent over the area, so the desktop shows. After the
  new build loads, the area still does not draw.
- Fix:
  - The old view instance and its window stay until the new build loads (`views.rs`, 15.8).
  - A lost surface makes a new window and surface at the next frame. A frame that the surface
    cannot give is an error on the view, not a silent return (`patina-gpu/src/viewport.rs`).
- Check: the model and gun shots open the view before **Run**. After the new build, the capture
  of the area shows the solid, and the view draws 90 % or more of its area.

## 3. The model view first-build error and other graphs

- Feedback: on the first build of the main graph of the model workbench, the model view showed an
  error. A close and an open of the workbench repairs it. In many graphs other than main, the
  model view does not show the 3D geometry.
- Cause: the view builds in Edit mode at the open. **Run** loads a Bake cluster while that build
  continues. The build then loads with the type IDs of the wrong mode, and the view shows an
  error. An error stops the asks of the view, so the view also does not change in other graphs.
- Fix: a view build that ends after a change of the cluster mode builds again in the new mode
  (`views.rs`, 15.8).
- Check: the model shot opens the view before **Run** and gets no error. Then it opens the
  **solids**, **sketches**, **seeds** and **sockets** graphs, selects a node in each, and the view
  shows its solid.

## 4. Maya controls in the 3D view

- Feedback: use the three mouse buttons as in Maya. A drag to the left and to the right also
  zooms, not only a drag up and down.
- Fix:
  - The viewport sends the mouse button and the Alt, Shift and Ctrl keys with the pointer
    down. It stops the context menu and the middle-button scroll (`controls/Viewport.tsx`).
  - Left drag orbits (also Alt and left drag). Middle drag pans. Right drag zooms with the sum
    of the horizontal and the vertical movement. The wheel zooms.
  - The three model views (model, gun, city) and the material preview use these controls.
- Check: an SDK test reads the button and the keys of a pointer down. The model shot drags the
  3D view with the left, the middle and the right button. Each drag changes the image.
- Spec: 15.8, the viewport input.

## 5. Material previews change during a drag

- Feedback: on the gpu workbench, a material node preview must change while a parameter drag
  continues, not only at the release.
- Cause: a slider sent its value only at the pointer up (`controls/NodeGui.tsx`).
- Fix: during a drag, the slider sends at most one value in each display frame. All values of one
  drag share one gesture number (`holdGuiGesture` in `api.ts`), so one undo restores the value
  before the drag.
- Check: the gpu shot drags the **Finish** slider. The depth changes before the release, and one
  undo restores it.
- Spec: 4.3, 9.1 and decision 11 of section 16.

## 6. Syntax colors for the assembly code

- Feedback: the program node of the computer workbench shows assembly code without syntax colors.
- Fix: a code field gets a `Syntax` from the node: the comment mark and the keywords (4.3). The
  editor colors the comments, the keywords, the labels, the numbers and the other names
  (`controls/codeColors.ts`). A colored layer goes over the text field, so the caret, the
  selection and the input do not change.
- Check: the computer shot shows the colors in the program node and in the Inspector.
